# android/gralloc: where these files come from

The driver can ask the device's gralloc HAL (IMapper 4.0) how a window or AHardwareBuffer is laid
out, instead of guessing from the buffer handle. That code is Mesa's own
(`src/util/u_gralloc/u_gralloc_imapper4_api.cpp`, MIT), but it is written against Android platform
interfaces that the NDK does not ship. This directory holds exactly what the build needs for it,
and nothing that would be loaded on the device.

## Headers (`include/`): Apache-2.0, The Android Open Source Project

Only the 51 headers the build reads. Full license text: `LICENSES/Apache-2.0.txt`.

| Path | AOSP project (revision used) |
|---|---|
| `include/utils/` | platform/system/core, libutils (a3b721a) |
| `include/hidl/` | platform/system/libhidl (b0ef829) |
| `include/fmq/` | platform/system/libfmq (2f538a2) |
| `include/android/binder_*.h` | platform/frameworks/native, libs/binder/ndk (4f463a6) |
| `include/gralloctypes/Gralloc4.h` | platform/frameworks/native, libs/gralloc/types (4f463a6) |
| `include/android/hardware/graphics/{common,mapper}/` | generated by hidl-gen (platform/system/tools/hidl d11716d) from platform/hardware/interfaces graphics/common 1.0-1.2 and graphics/mapper 4.0 (1a56e38) |
| `include/android/hidl/{base,manager}/` | generated by hidl-gen from platform/system/libhidl transport/base 1.0 and transport/manager 1.0 (b0ef829) |
| `include/aidl/android/hardware/graphics/common/` | generated by the SDK's aidl (NDK backend) from platform/hardware/interfaces graphics/common/aidl (1a56e38); `BufferUsage.h` written by hand with the frozen interface's values |

The generated headers carry no license header of their own; they are generated from the Apache-2.0
interface definitions named above. None of the headers was modified.

## `abi_override/c++/v1/__config_site`: Apache-2.0 WITH LLVM-exception, the LLVM Project

The NDK's libc++ configuration header with one change, marked in the file: the inline namespace is
`__1` (the Android platform's libc++) instead of `__ndk1`. Only the IMapper file is compiled with it,
because the platform libraries it calls pass `std::` types across their interface.

## Link stubs (`stubs.txt`, `mkstubs.py`)

The driver has to be linked against `libgralloctypes.so`, `libhidlbase.so`, `libutils.so`,
`android.hardware.graphics.mapper@4.0.so` and the platform `libc++.so`. Instead of copies of a
device's libraries, `mkstubs.py` builds empty libraries with the same names and exported symbols
(listed in `stubs.txt`, taken from an Android 12 system image) at build time. They contain no code
from those libraries and are never shipped: on the device, Android loads its own.

`stubs.txt` and `mkstubs.py` are part of this project (MIT).
